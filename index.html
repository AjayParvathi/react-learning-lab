Project Setup

Everything you need to go from zero to a running React app. Start here before writing any React code.

Step 1 — Install Node.js
React runs on Node.js. Download the LTS version from nodejs.org. Node comes with npm, the package manager you'll use every day.
node --version    # should be v18 or higher (v22 recommended)
npm --version     # should be v9 or higher
Step 2 — Create a project with Vite
Vite is the modern build tool the React team recommends. It starts in under 1 second. Create React App (CRA) is deprecated — don't start new projects with it.
# JavaScript project
npm create vite@latest my-app -- --template react
cd my-app && npm install && npm run dev

# TypeScript project (recommended for real apps)
npm create vite@latest my-app -- --template react-ts
Vite starts in ~300ms. CRA took 30+ seconds. Same React, just a much faster toolchain.
What each file does
my-app/
├── node_modules/       # installed packages — never edit this
├── public/             # static files (favicon, robots.txt)
├── src/
│   ├── main.jsx        # entry point — mounts React to the page
│   ├── App.jsx         # your root component — start building here
│   └── index.css       # global styles
├── index.html          # the one HTML file — React fills #root inside it
├── vite.config.js      # Vite config (rarely need to touch this)
└── package.json        # project info + list of all dependencies
How React connects to the page
index.html
<!-- Just one div.
   React fills this. -->
<div id="root"></div>
main.jsx
import ReactDOM from 'react-dom/client'
import App from './App'
import './index.css'

ReactDOM.createRoot(
  document.getElementById('root')
).render(
  <React.StrictMode>
    <App />
  </React.StrictMode>

React.StrictMode runs your components twice in development to find bugs. Does nothing in production.

Environment variables — store secrets safely
Never hardcode API keys in source code. Store them in a .env file and always add it to .gitignore.
# .env file — in project root, never committed to Git
VITE_API_URL=https://api.example.com
VITE_API_KEY=your-secret-key
# Using them in code — Vite requires VITE_ prefix
const url = import.meta.env.VITE_API_URL
const key = import.meta.env.VITE_API_KEY
These vars are bundled into your JavaScript bundle — users can see them. Never put database passwords here. Use a backend proxy for truly sensitive operations.

JSX

JSX is the syntax that lets you write HTML-like code inside JavaScript. React compiles it to regular function calls.

You write
const el = <h1>Hello!</h1>
React compiles to
const el = React.createElement(
  'h1', null, 'Hello!'
)
5 rules of JSX
#RuleExample
1One root element per returnUse <>...</> or <div>...</div>
2className not class<div className="box">
3All tags must close<img /> <input /> <br />
4JavaScript goes in curly braces{name} {2+2} {ok ? 'Yes' : 'No'}
5camelCase inline stylesfontSize not font-size
JSX in practice
const name = 'Aj'
const isAdmin = true

function App() {
  return (
    <>
      <h1 style={{ fontSize: '24px', color: 'teal' }}>
        Hello, {name}!
      </h1>

      {/* conditional rendering */}
      {isAdmin && <p>You have admin access</p>}
      {isAdmin ? <AdminPanel /> : <UserPanel />}

      <input type="text" placeholder="Search..." />
    </>
  )
}
Comments in JSX use {/* like this */} — not // outside curly braces.
Fragments — avoid extra DOM nodes
// Short syntax — use this 99% of the time
return (
  <>
    <h1>Title</h1>
    <p>Body</p>
  </>
)

// Long syntax — required when you need to pass a key prop in a list
return (
  <React.Fragment key={item.id}>
    <dt>{item.term}</dt>
    <dd>{item.description}</dd>
  </React.Fragment>
)

Components & Props

Components are functions that return JSX. Props are the inputs you pass to them — like function arguments.

Function declaration
function Welcome({ name }) {
  return <h1>Hi, {name}!</h1>
}
Arrow function
const Welcome = ({ name }) => (
  <h1>Hi, {name}!</h1>
)
Props — passing data in
<Welcome name="Aj" />
<Button label="Submit" color="blue" size={16} disabled={false} />

// Default prop values
const Button = ({ label = 'Click me', color = 'blue', disabled = false }) => (
  <button style={{ color }} disabled={disabled}>{label}</button>
)
The children prop
Anything placed between opening and closing tags becomes children. Used for wrapper components like cards, modals, layouts.
const Card = ({ children, title }) => (
  <div className="card">
    {title && <h2>{title}</h2>}
    {children}
  </div>
)

// Usage
<Card title="Profile">
  <img src="avatar.jpg" alt="avatar" />
  <p>Hello from inside the card!</p>
</Card>
Rendering lists
Use .map() to turn an array into JSX. The key prop must be a stable, unique ID — not the array index when items can be reordered or deleted.
const users = [
  { id: 1, name: 'Aj', role: 'Admin' },
  { id: 2, name: 'Sam', role: 'User' },
]

const UserList = () => (
  <ul>
    {users.map(user => (
      <li key={user.id}>{user.name} — {user.role}</li>
    ))}
  </ul>
)
Never use array index as key if the list can be filtered, sorted, or have items added/removed. Use a real unique ID.
Conditional rendering
// Ternary — show one of two things
{isLoggedIn ? <Dashboard /> : <Login />}

// Short-circuit — show something or nothing
{hasNotifications && <Badge count={5} />}

// Early return — cleanest for complex conditions
const UserCard = ({ user }) => {
  if (!user) return <p>No user found</p>
  if (user.banned) return <p>Account suspended</p>
  return <div>{user.name}</div>
}
Prop spreading — passing many props at once
// Instead of writing each prop manually, spread them
const inputProps = {
  type: 'email', placeholder: 'Email', required: true
}
<input {...inputProps} />

// Very useful in wrapper components
const MyInput = ({ label, ...rest }) => (
  <div>
    <label>{label}</label>
    <input {...rest} />  {/* passes all remaining props */}
  </div>
)

Events

React events are camelCase and take a function reference. They work identically across all browsers.

Always pass a reference — not a call
const Button = () => {
  const handleClick = () => console.log('clicked!')

  return (
    <>
      <button onClick={handleClick}>OK</button>      {/* correct */}
      <button onClick={handleClick()}>Bad</button>   {/* runs on render! */}
    </>
  )
}
Passing arguments — wrap in an arrow function
const List = ({ users }) => {
  const handleDelete = (id, name) => {
    console.log(`Delete ${name} (id: ${id})`)
  }

  return (
    <ul>
      {users.map(u => (
        <li key={u.id}>
          {u.name}
          <button onClick={() => handleDelete(u.id, u.name)}>Delete</button>
        </li>
      ))}
    </ul>
  )
}
The event object
const handleChange  = (e) => console.log(e.target.value)   // input value
const handleSubmit  = (e) => { e.preventDefault(); submit() }
const handleKeyDown = (e) => { if (e.key === 'Enter') submit() }
const handleCheck   = (e) => console.log(e.target.checked)  // checkbox
Common events
EventWhen it fires
onClickUser clicks anything
onChangeInput / select / textarea value changes
onSubmitForm is submitted
onFocus / onBlurInput gains / loses focus
onMouseEnter / onMouseLeaveMouse enters / leaves element
onKeyDown / onKeyUpKey is pressed / released
onScrollElement is scrolled

All React Hooks

Hooks are functions starting with use. Call them only at the top level of your component — never inside loops, conditions, or nested functions.

State

useState — store a changing value

The most used hook. When state changes, the component re-renders.

▶
Analogy: a sticky note React watches
import { useState } from 'react'

const Counter = () => {
  const [count, setCount] = useState(0)
  //     ^ value   ^ setter  ^ initial value

  return (
    <div>
      <p>Count: {count}</p>
      <button onClick={() => setCount(prev => prev + 1)}>+</button>
      <button onClick={() => setCount(0)}>Reset</button>
    </div>
  )
}

// Object in state — always spread, never mutate directly
const [user, setUser] = useState({ name: '', email: '' })
setUser(prev => ({ ...prev, name: 'Aj' }))
Use prev => prev + 1 (function form) when the new value depends on the old one. Safe even when React batches updates.

useReducer — complex state logic

Like useState but centralises all update logic in one reducer function. Great for 3+ related state values.

▶
import { useReducer } from 'react'

const reducer = (state, action) => {
  switch (action.type) {
    case 'increment': return { ...state, count: state.count + 1 }
    case 'decrement': return { ...state, count: state.count - 1 }
    case 'reset':     return { count: 0 }
    case 'setTo':     return { count: action.payload }
    default: throw new Error('Unknown action: ' + action.type)
  }
}

const Counter = () => {
  const [state, dispatch] = useReducer(reducer, { count: 0 })

  return (
    <div>
      <p>{state.count}</p>
      <button onClick={() => dispatch({ type: 'increment' })}>+</button>
      <button onClick={() => dispatch({ type: 'setTo', payload: 10 })}>Set 10</button>
    </div>
  )
}
Refs

useRef — access DOM or store a silent value

Holds a value that persists across renders but does NOT trigger re-render when changed.

▶
import { useRef, useEffect } from 'react'

// Use 1: Access a DOM element directly
const AutoFocus = () => {
  const inputRef = useRef(null)
  useEffect(() => { inputRef.current.focus() }, [])
  return <input ref={inputRef} placeholder="Auto-focused!" />
}

// Use 2: Store a value without re-rendering
// Perfect for: timer IDs, previous values, render counts
const Timer = () => {
  const intervalRef = useRef(null)
  const start = () => { intervalRef.current = setInterval(() => console.log('tick'), 1000) }
  const stop  = () => clearInterval(intervalRef.current)
  return <><button onClick={start}>Start</button><button onClick={stop}>Stop</button></>
}

useImperativeHandle — choose what ref exposes

Controls which methods a parent can call on a child via ref.

▶
import { useRef, useImperativeHandle } from 'react'

// React 19 — ref is a regular prop (no forwardRef needed)
const FancyInput = ({ ref, ...props }) => {
  const inputRef = useRef()

  useImperativeHandle(ref, () => ({
    focus:    () => inputRef.current.focus(),
    clear:    () => { inputRef.current.value = '' },
    getValue: () => inputRef.current.value,
  }))

  return <input ref={inputRef} {...props} />
}

const Parent = () => {
  const ref = useRef()
  return (
    <div>
      <FancyInput ref={ref} />
      <button onClick={() => ref.current.focus()}>Focus</button>
      <button onClick={() => ref.current.clear()}>Clear</button>
    </div>
  )
}
In React 19, ref is a regular prop. The old forwardRef() wrapper is no longer needed.
Effects

useEffect — run code after render

For side effects: fetching data, subscriptions, timers, DOM manipulation.

▶
import { useEffect, useState } from 'react'

const UserList = () => {
  const [users, setUsers] = useState([])

  useEffect(() => {
    // Define async inside the effect — can't make the effect itself async
    const fetchUsers = async () => {
      const res  = await fetch('/api/users')
      const data = await res.json()
      setUsers(data)
    }
    fetchUsers()
  }, [])   // [] = run only once when component mounts

  return <ul>{users.map(u => <li key={u.id}>{u.name}</li>)}</ul>
}
Dependency arrayWhen it runs
OmittedAfter every render
[] emptyOnce on mount
[id]On mount + when id changes
// Cleanup — return a function to clean up before next run or unmount
useEffect(() => {
  const sub = subscribeToEvents(userId, handler)
  return () => sub.unsubscribe()
}, [userId])
Always clean up subscriptions, event listeners, and timers. Missing cleanup causes memory leaks.

useLayoutEffect — run before browser paints

Same as useEffect but fires synchronously after DOM updates. Use only when measuring DOM size/position.

▶
import { useLayoutEffect, useRef, useState } from 'react'

const Tooltip = ({ children }) => {
  const ref = useRef()
  const [height, setHeight] = useState(0)

  useLayoutEffect(() => {
    // Reads DOM before paint — no flicker
    setHeight(ref.current.getBoundingClientRect().height)
  }, [])

  return <div ref={ref}>{children} (height: {height}px)</div>
}
Use useEffect by default. Switch to useLayoutEffect only if you see visible flickering.
Performance

useMemo — cache an expensive calculation

Only recalculates when dependencies change. Skips the work on every other render.

▶
import { useMemo } from 'react'

const ProductList = ({ products, filterText, sortKey }) => {
  const filtered = useMemo(() => {
    return products
      .filter(p => p.name.toLowerCase().includes(filterText.toLowerCase()))
      .sort((a, b) => a[sortKey] > b[sortKey] ? 1 : -1)
  }, [products, filterText, sortKey])

  return <ul>{filtered.map(p => <li key={p.id}>{p.name}</li>)}</ul>
}
Only use useMemo for genuinely slow calculations. The React Compiler (React 19, opt-in) automates this — check the docs.

useCallback — cache a function reference

Returns the same function object between renders. Needed when passing functions to memoized children.

▶
import { useCallback, memo, useState } from 'react'

const Parent = () => {
  const [count, setCount] = useState(0)

  // Without useCallback: new function every render → Child re-renders unnecessarily
  // With useCallback: same reference → Child skips re-render
  const handleAction = useCallback((id) => {
    console.log('action on', id)
  }, [])   // no deps = never recreated

  return (
    <div>
      <button onClick={() => setCount(c => c + 1)}>Count: {count}</button>
      <ExpensiveList onAction={handleAction} />
    </div>
  )
}

// memo() is required for useCallback to have any effect
const ExpensiveList = memo(({ onAction }) => (
  <li onClick={() => onAction(1)}>Item</li>
))
Context & Transitions (React 18+)

useContext — read context values

Reads the value from the nearest matching Provider above in the tree.

▶
import { createContext, useContext } from 'react'

const ThemeContext = createContext('light')

const App = () => (
  <ThemeContext.Provider value="dark">
    <Page />
  </ThemeContext.Provider>
)

const Page = () => {
  const theme = useContext(ThemeContext)
  return <div className={theme}>Theme: {theme}</div>
}

useTransition — non-urgent updates 18+

Keeps UI responsive by letting React prioritise user input over expensive state updates.

▶
import { useState, useTransition } from 'react'

const Search = ({ items }) => {
  const [query, setQuery]   = useState('')
  const [results, setResults] = useState(items)
  const [isPending, startTransition] = useTransition()

  const handleChange = (e) => {
    setQuery(e.target.value)       // urgent — update immediately

    startTransition(() => {        // non-urgent — React can delay this
      setResults(items.filter(i => i.toLowerCase().includes(e.target.value.toLowerCase())))
    })
  }

  return (
    <div>
      <input value={query} onChange={handleChange} />
      {isPending && <span>Updating...</span>}
      <ul>{results.map(r => <li key={r}>{r}</li>)}</ul>
    </div>
  )
}

useDeferredValue — defer a value 18+

Like useTransition but for values you receive (props you don't control). Deferred copy lags behind to keep input snappy.

▶
import { useState, useDeferredValue, memo } from 'react'

const SearchPage = () => {
  const [query, setQuery]   = useState('')
  const deferredQuery = useDeferredValue(query)
  // Input: always snappy (uses query)
  // Heavy list: updates when React has time (uses deferredQuery)

  return (
    <div>
      <input value={query} onChange={e => setQuery(e.target.value)} />
      <SlowList filter={deferredQuery} />
    </div>
  )
}

const SlowList = memo(({ filter }) => {
  return <ul>{bigData.filter(i => i.includes(filter)).map(i => <li key={i}>{i}</li>)}</ul>
})
useTransition — you control the setter. useDeferredValue — you only receive the value from a prop or external source.
Utility (React 18+)

useId — stable unique IDs 18+

Generates an ID that is identical on server and client. Use for label/input pairs and ARIA attributes.

▶
import { useId } from 'react'

const FormField = ({ label, type = 'text' }) => {
  const id = useId()
  return (
    <div>
      <label htmlFor={id}>{label}</label>
      <input id={id} type={type} />
    </div>
  )
}

// Multiple IDs from one hook call — use suffixes
const Form = () => {
  const id = useId()
  return (
    <div>
      <input id={`${id}-name`} aria-label="Name" />
      <input id={`${id}-email`} aria-label="Email" />
    </div>
  )
}

useSyncExternalStore — subscribe to external stores 18+

The safe way to read from stores outside React (browser APIs, third-party libraries). Used by Redux/Zustand internally.

▶
import { useSyncExternalStore } from 'react'

// Example: window.innerWidth that updates on resize
const useWindowWidth = () => useSyncExternalStore(
  (onChange) => {
    window.addEventListener('resize', onChange)
    return () => window.removeEventListener('resize', onChange)
  },
  () => window.innerWidth,  // client snapshot
  () => 1024                // server/SSR snapshot
)

const App = () => {
  const width = useWindowWidth()
  return <p>Window: {width}px</p>
}

useDebugValue — label hooks in DevTools

Adds a readable label to your custom hook in React DevTools. Zero effect in production.

▶
import { useState, useDebugValue } from 'react'

const useOnlineStatus = () => {
  const [isOnline, setIsOnline] = useState(navigator.onLine)

  // DevTools shows: "OnlineStatus: Online" or "OnlineStatus: Offline"
  useDebugValue(isOnline ? 'Online' : 'Offline')

  return isOnline
}

React 19 — New Hooks

React 19 became stable in December 2024. It introduced hooks for async actions, optimistic UI, and simplified form handling — the biggest additions since hooks launched in 2019.

useActionState — async form actions React 19

Manages an async action's result, pending state, and the action function in one hook.

▶
import { useActionState } from 'react'

// Define the action — receives previous state + form data
async function submitContact(prevState, formData) {
  const email   = formData.get('email')
  const message = formData.get('message')
  try {
    await sendEmail({ email, message })
    return { success: true, error: null }
  } catch (err) {
    return { success: false, error: err.message }
  }
}

const ContactForm = () => {
  const [state, formAction, isPending] = useActionState(
    submitContact,
    { success: false, error: null }   // initial state
  )

  return (
    <form action={formAction}>
      <input name="email" type="email" required />
      <textarea name="message" required />
      <button type="submit" disabled={isPending}>
        {isPending ? 'Sending...' : 'Send'}
      </button>
      {state.success && <p>Message sent!</p>}
      {state.error   && <p>Error: {state.error}</p>}
    </form>
  )
}
Eliminates 4–5 separate useState/useEffect calls for async form handling. Much cleaner.

useFormStatus — read parent form state React 19

Reads whether the nearest parent form is submitting. Makes self-aware reusable submit buttons.

▶
import { useFormStatus } from 'react-dom'
// ⚠ Import from 'react-dom', not 'react'

const SubmitButton = ({ children = 'Submit' }) => {
  const { pending } = useFormStatus()
  // pending: true while the form action is running

  return (
    <button type="submit" disabled={pending}>
      {pending ? 'Loading...' : children}
    </button>
  )
}

// Works automatically inside any form
const MyForm = () => (
  <form action={myAction}>
    <input name="query" />
    <SubmitButton>Search</SubmitButton>
  </form>
)
Must be rendered inside a <form> — cannot be in the same component as the form itself.

useOptimistic — instant UI updates React 19

Shows the expected result immediately while async runs. Auto-reverts if the operation fails.

▶
import { useOptimistic } from 'react'

const MessageList = ({ messages, sendMessage }) => {
  const [optimisticMessages, addOptimistic] = useOptimistic(
    messages,
    (current, newMsg) => [
      ...current,
      { id: Date.now(), text: newMsg, sending: true }
    ]
  )

  const handleSend = async (text) => {
    addOptimistic(text)         // instantly show in UI
    await sendMessage(text)     // send to server
    // if sendMessage throws, UI reverts to real messages automatically
  }

  return (
    <ul>
      {optimisticMessages.map(msg => (
        <li key={msg.id} style={{ opacity: msg.sending ? 0.5 : 1 }}>
          {msg.text} {msg.sending && '(sending...)'}
        </li>
      ))}
    </ul>
  )
}
Like WhatsApp showing your message instantly before the server confirms it. Automatic rollback on failure.

use() — read Promises and Context anywhere React 19

The only hook that can be called inside conditionals and loops. Suspends the component until a Promise resolves.

▶
import { use, Suspense } from 'react'

// With a Promise — component suspends until resolved
const UserProfile = ({ userPromise }) => {
  const user = use(userPromise)   // pauses here until ready
  return <h1>{user.name}</h1>
}

const App = () => {
  const userPromise = fetch('/api/user').then(r => r.json())
  return (
    <Suspense fallback={<p>Loading...</p>}>
      <UserProfile userPromise={userPromise} />
    </Suspense>
  )
}

// With Context — can be inside conditionals (unlike useContext)
const Button = ({ isDark }) => {
  if (isDark) {
    const theme = use(ThemeContext)  // OK inside an if block!
    return <button className={theme}>Button</button>
  }
  return <button>Button</button>
}
use() is the only hook that can be inside if, for, etc. All other hooks must be at the top level, unconditionally.

Custom Hooks

A custom hook is a function starting with use that calls other hooks inside. Extracts and shares stateful logic between components without repetition.

useFetch — reusable data loading
import { useState, useEffect, useCallback } from 'react'

const useFetch = (url) => {
  const [data, setData]       = useState(null)
  const [loading, setLoading] = useState(true)
  const [error, setError]     = useState(null)

  const fetchData = useCallback(async () => {
    try {
      setLoading(true); setError(null)
      const res = await fetch(url)
      if (!res.ok) throw new Error(`HTTP ${res.status}`)
      setData(await res.json())
    } catch (err) {
      setError(err.message)
    } finally {
      setLoading(false)
    }
  }, [url])

  useEffect(() => { fetchData() }, [fetchData])

  return { data, loading, error, refetch: fetchData }
}

// Usage
const UserPage = () => {
  const { data: users, loading, error, refetch } = useFetch('/api/users')

  if (loading) return <p>Loading...</p>
  if (error)   return <p>{error} <button onClick={refetch}>Retry</button></p>
  return <ul>{users.map(u => <li key={u.id}>{u.name}</li>)}</ul>
}
useLocalStorage — persist state across sessions
import { useState, useEffect } from 'react'

const useLocalStorage = (key, initialValue) => {
  const [value, setValue] = useState(() => {
    try {
      const item = localStorage.getItem(key)
      return item ? JSON.parse(item) : initialValue
    } catch { return initialValue }
  })

  useEffect(() => {
    try { localStorage.setItem(key, JSON.stringify(value)) } catch {}
  }, [key, value])

  return [value, setValue]
}

// Works exactly like useState but survives page refresh

  const [theme, setTheme] = useLocalStorage('theme', 'dark')
  return (
    <button onClick={() => setTheme(t => t === 'dark' ? 'light' : 'dark')}>
      {theme} mode
    </button>
  )
}

import { useState, useEffect } from 'react'

const useDebounce = (value, delay = 400) => {
  const [debounced, set] = useState(value)
  useEffect(() => {
    const t = setTimeout(() => set(value), delay)
    return () => clearTimeout(t)
  }, [value, delay])
  return debounced
}

Full auth context pattern
import { createContext, useContext, useState, useCallback } from 'react'

// 1. Create
const AuthContext = createContext(null)

// 2. Provider with state + actions
export const AuthProvider = ({ children }) => {
  const [user, setUser]     = useState(null)
  const [loading, setLoading] = useState(false)

  const login = useCallback(async (email, password) => {
    setLoading(true)
    try {
      const user = await loginAPI(email, password)
      setUser(user)
    } finally { setLoading(false) }
  }, [])

  const logout = useCallback(() => {
    setUser(null)
    localStorage.removeItem('token')
  }, [])

  return (
    <AuthContext.Provider value={{ user, loading, login, logout }}>
      {children}
    </AuthContext.Provider>
  )
}

// 3. Custom hook with error guard
export const useAuth = () => {
  const ctx = useContext(AuthContext)
  if (!ctx) throw new Error('useAuth must be inside AuthProvider')
  return ctx
}

// 4. Wrap in main.jsx
// <AuthProvider><App /></AuthProvider>

// 5. Consume anywhere — no prop drilling
const NavBar = () => {
  const { user, logout } = useAuth()
  return (
    <nav>
      {user ? <button onClick={logout}>Logout</button> : <a href="/login">Login</a>}
    </nav>
  )
}
Context best practices
1
Split by concern

One context for auth, one for theme, one for cart. A single giant AppContext is a mess.

2
Always wrap with a custom hook

Expose useAuth(), not raw useContext(AuthContext). Adds error guard, easier to refactor.

3
Avoid for high-frequency updates

Every consumer re-renders when context changes. Mouse position, scroll values → use useRef or Zustand instead.

Forms are in almost every app. React gives you full control. For complex forms, use React Hook Form — it's the current industry standard.

Controlled inputs with validation
import { useState } from 'react'

const SignupForm = () => {
  const [form, setForm]     = useState({ name: '', email: '', password: '' })
  const [errors, setErrors] = useState({})

  const handleChange = (e) => {
    const { name, value } = e.target
    setForm(prev => ({ ...prev, [name]: value }))
    setErrors(prev => ({ ...prev, [name]: '' }))  // clear error on type
  }

  const validate = () => {
    const errs = {}
    if (!form.name)                  errs.name     = 'Name is required'
    if (!form.email.includes('@'))   errs.email    = 'Valid email required'
    if (form.password.length < 8)    errs.password = 'Min 8 characters'
    return errs
  }

  const handleSubmit = (e) => {
    e.preventDefault()
    const errs = validate()
    if (Object.keys(errs).length) { setErrors(errs); return }
    console.log('Valid, submitting:', form)
  }

  return (
    <form onSubmit={handleSubmit}>
      <input name="name"     value={form.name}     onChange={handleChange} />
      {errors.name     && <p className="error">{errors.name}</p>}
      <input name="email"    value={form.email}    onChange={handleChange} />
      {errors.email    && <p className="error">{errors.email}</p>}
      <input name="password" value={form.password} onChange={handleChange} type="password" />
      {errors.password && <p className="error">{errors.password}</p>}
      <button type="submit">Sign Up</button>
    </form>
  )
}

API & Data Fetching

React has no built-in data fetching. For simple cases: fetch + useEffect. For real apps: TanStack Query — the current industry standard for server state.

fetch + useEffect — foundational pattern
import { useState, useEffect } from 'react'

const UserProfile = ({ userId }) => {
  const [user, setUser]       = useState(null)
  const [loading, setLoading] = useState(true)
  const [error, setError]     = useState(null)

  useEffect(() => {
    let cancelled = false   // prevent setting state after unmount

    const fetchUser = async () => {
      try {
        setLoading(true)
        const res = await fetch(`/api/users/${userId}`)
        if (!res.ok) throw new Error(`Error ${res.status}`)
        const data = await res.json()
        if (!cancelled) setUser(data)
      } catch (err) {
        if (!cancelled) setError(err.message)
      } finally {
        if (!cancelled) setLoading(false)
      }
    }

    fetchUser()
    return () => { cancelled = true }   // cleanup on unmount or userId change
  }, [userId])

  if (loading) return <div>Loading...</div>
  if (error)   return <div>Error: {error}</div>
  return <div>{user?.name}</div>
}

Key TypeScript rules for React
1
Never use any

It disables all type checking. Use unknown if you genuinely don't know the type, then narrow it.

2
interface for objects, type for unions

Use interface User {} for objects. Use type Status = 'a' | 'b' for union types.

3
Optional chaining

Use user?.name instead of user && user.name to safely access potentially null values.

4
Library types come included

React Router, TanStack Query, Axios — all include TypeScript types. No separate @types install needed.

Zustand — simple, no-boilerplate global state
npm install zustand
import { create } from 'zustand'

const useCartStore = create((set, get) => ({
  items: [],

  addItem: (item) => set(state => ({
    items: [...state.items, item]
  })),

  removeItem: (id) => set(state => ({
    items: state.items.filter(i => i.id !== id)
  })),

  clearCart: () => set({ items: [] }),

  // Computed — derived from current state
  get total()     { return get().items.reduce((sum, i) => sum + i.price, 0) },
  get itemCount() { return get().items.length },
}))

// Use in any component — NO Provider needed!
const CartIcon = () => {
  const itemCount = useCartStore(state => state.itemCount)
  return <button>Cart ({itemCount})</button>
}

const ProductCard = ({ product }) => {
  const addItem = useCartStore(state => state.addItem)
  return <button onClick={() => addItem(product)}>Add to cart</button>
}
Zustand is what most teams reach for in 2025. Minimal boilerplate, no Provider, easy to test.
Redux Toolkit — for large, structured apps
RTK is the modern way to use Redux. Never use plain Redux without RTK — the boilerplate is massive and error-prone.
npm install @reduxjs/toolkit react-redux
import { createSlice, configureStore } from '@reduxjs/toolkit'

const counterSlice = createSlice({
  name: 'counter',
  initialState: { value: 0 },
  reducers: {
    increment: state => { state.value += 1 },   // Immer lets you "mutate"
    decrement: state => { state.value -= 1 },
    setTo:     (state, action) => { state.value = action.payload },
  },
})
export const { increment, decrement, setTo } = counterSlice.actions

const store = configureStore({ reducer: { counter: counterSlice.reducer } })

// Use in components
import { useSelector, useDispatch } from 'react-redux'

const Counter = () => {
  const count    = useSelector(state => state.counter.value)
  const dispatch = useDispatch()
  return <div><p>{count}</p><button onClick={() => dispatch(increment())}>+</button></div>
}
Decision guide
1
Start with useState + useReducer

Covers most small-to-medium apps. Zero dependencies.

2
Add TanStack Query for all server data

This alone eliminates most state management complexity — server data shouldn't live in Redux or Zustand.

3
Add Zustand for complex client state

Shopping cart, notifications, multi-step forms shared across many routes.

4
Redux Toolkit for large teams

RTK's strict conventions help when many developers touch the same state. Overkill for teams under ~5.

Virtual DOM & React Internals

Understanding how React works under the hood helps you write better code and debug harder problems.

Why the Virtual DOM exists
Without React
// 1000 DOM writes
for (let i = 0; i < 1000; i++) {
  el.textContent = newValues[i]
}
// Each write can trigger reflow/repaint
// Very slow for large updates
With React
// React diffs old vs new Virtual DOM
// Computes the minimal set of changes
// Applies them in one batch to the DOM
setItems(newItems)
// Could be 1 DOM write instead of 1000
Reconciliation — how React decides what changed
1
Render phase

React calls your component functions and builds a new tree of JS objects (Virtual DOM). Fast — happens entirely in memory.

2
Diff phase

React compares new tree vs previous tree using a heuristic O(n) algorithm (not naïve O(n³)).

3
Commit phase

React applies only the minimal set of changes to the real DOM. This is the slow step — React minimises it.

The key prop — how React tracks list items
// Without key — React can't tell which item changed
{items.map(item => <li>{item.name}</li>)}

// Index as key — breaks when list is sorted, filtered, or modified
{items.map((item, i) => <li key={i}>{item.name}</li>)}

// Stable unique ID — correct
{items.map(item => <li key={item.id}>{item.name}</li>)}

// Intentional remount trick — change key to reset all state in a component
<UserProfile key={userId} />  // mounts fresh whenever userId changes
React Fiber — the engine behind React
React 16 rewrote the reconciler as "Fiber" — a linked-list structure that can pause, resume, and prioritise rendering work. This enables everything in modern React:
FeatureHow Fiber enables it
Concurrent ModePauses low-priority renders to process user input first
useTransitionMarks state updates as interruptible / low priority
SuspensePauses a subtree while waiting for data or code
Error BoundariesCatches errors in a subtree without crashing everything
Time SlicingBreaks long renders into chunks so the browser never freezes

JavaScript first

Components as functions, props as arguments, JSX as syntax sugar for createElement.

useState + useEffect
